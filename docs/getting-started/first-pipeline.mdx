Build and run your first machine learning pipeline in under 10 minutes using the TangleML editor's drag-and-drop interface.

## Overview

This guide walks you through creating a complete XGBoost machine learning pipeline using TangleML's standard library components. You'll learn how to:

- Access and use standard library components
- Connect components to create data flows
- Run and monitor pipeline execution
- Troubleshoot common issues

For a tour of the editor itself — its menus, windows, and shortcuts — see [Pipeline Editor](/docs/user-guide/pipeline-editor).

## Accessing standard library components

The standard library provides pre-built components for common ML tasks. You reach it from the **Component Search** window, which is docked on the left of the editor by default:

1. Leave the **Search components...** box empty to see the component folders.
2. Expand **Standard library**, then **Quick start** for beginner-friendly components.
3. Browse the other folders for components organized by category, or type in the search box to find a component by name.

:::tip
Each component in the standard library is fully documented. To see implementation details, click the ⓘ button on a component's row and open the **Implementation** tab.
:::

## Building your first pipeline

### Step 1: Add a data source

Start by adding the **Chicago Taxi Trips dataset** component to your canvas:

1. Find the component in the **Quick start** folder, or type `Chicago` in the search box.
2. Drag and drop it onto the canvas.
3. This component fetches data from Chicago's open API using a simple cURL command.

You can run the pipeline at this point (see [Step 5](#step-5-running-and-troubleshooting-your-pipeline)). In the run, click the task and open the **Artifacts** tab of the **Properties** window to see the data it fetched.

### Step 2: Add training and prediction components

Next, add the ML components from the same **Quick start** folder:

1. Drag **Train XGBoost model on CSV** onto the canvas.
2. Drag **Xgboost predict on CSV** onto the canvas.
3. You'll now have three components ready to connect.

### Step 3: Connect components

Create the data flow by connecting component outputs to inputs:

1. **Connect the dataset to training:**

   - Drag from the `Table` output of **Chicago Taxi Trips dataset**.
   - Connect to the `training data` input of **Train XGBoost model on CSV**.

2. **Connect to prediction component:**
   - Connect the same dataset `Table` output to the prediction component's `data` input.
   - Connect the training component's `model` output to the prediction component's `model` input.

:::tip
You'll notice inputs marked in red on the canvas. These are required inputs that still need a value. The pipeline can't run until all validation errors are resolved: the **Submit Run** button in the menu bar turns red and reads **Pipeline has validation errors** on hover. The **Pipeline Details** window lists the problems, and its **Fix** button walks you through them. We'll fix these in the next step.
:::

### Step 4: Configure required parameters

Some components need additional configuration:

1. Click the **Train XGBoost model on CSV** task. The **Properties** window opens on its **Arguments** tab.
2. Set **label column name** (for example, `tips`).
3. Set the same label column name for the prediction task.
4. The red validation markers disappear once every required input is set.

:::tip
TangleML automatically saves your canvas changes every time you make a change. To check, hover the cloud icon at the right of the menu bar: it reads **Last saved at** followed by the time. Click it to save immediately.
:::

### Step 5: Running and troubleshooting your pipeline

Now that all components are connected, let's run the pipeline:

1. Click the green **Submit Run** button at the right of the menu bar, or choose **Runs → Submit Run**.
2. A **Pipeline successfully submitted** notification appears. Click **View Run** in it to open the run.
3. Components will transition through states:
   - `Queued` → `Pending` → `Running` → `Succeeded` (or `Failed`)

The editor stays open after you submit, so you can keep working while the run executes. The **Recent Runs** window lists the runs of this pipeline.

You'll see that the component failed. That's OK! Let's troubleshoot it.

#### Use logs to troubleshoot pipeline failures

The most common way to troubleshoot a pipeline failure is to check the logs.

1. Click the failed task's **Open Logs** button, or click the task and open the **Logs** tab in the **Properties** window.
    * Use **View fullscreen** to read the logs in full screen, **Pop out logs** to move them into their own window, or **Open logs in a new tab**.
    * Search the logs by pressing **CMD/CTRL + F** to search for specific text in the logs.
    
    Different components produce different error messages. You need to know specifics of the component to troubleshoot the pipeline failure.
2. You'll see an error message related to our component:
    ```
    Check failed: valid: Label contains NaN, infinity or a value too large.
    ```
  
    Looks like some of the rows in our dataset have empty values in the label column. 
3. We'll fix this in the next step using a standard library component.

To return to the editor, click **Inspect pipeline** in the **Run Tools** window, or choose **Run → Inspect Pipeline**. See [Run View](/docs/user-guide/run-view) for everything else the run view offers.

#### Use components to fix data quality issues

1. Search for **Fill all missing values using Pandas on CSV data** and drag it onto the canvas between your dataset and training components.
2. Redirect connections:
     - Connect dataset `Table` output → Fill missing values `table` input.
     - Connect Fill missing values `transformed table` output → Training `training data` and Prediction `data` inputs.
3. Re-run the pipeline by clicking **Submit Run** in the editor again.

:::note
Notice that some tasks executed instantly when you reran the pipeline. 
TangleML caches deterministic component results. When you re-run a pipeline, any tasks with identical component digest and inputs will reuse cached outputs, dramatically speeding up iteration time. You'll see cached components complete instantly with a **Succeeded** status.
:::

### Step 6: Using input nodes for repeated values

Avoid repetition and make your pipeline more maintainable by using input nodes as variables:

1. **Add an input node:**
   - In the **Component Search** window, with the search box empty, open **Inputs & Outputs** and drag an **Input Node** onto the canvas.
   - In the **Properties** window, give it a descriptive **Name** (for example, `label_column_name`).
   - Set its **Value** to `tips` (or your label column name).

2. **Connect the input node:**
   - Connect the input node's output to both:
     - Train XGBoost model's `label column name` input
     - Xgboost predict's `label column name` input

:::tip
There is a shortcut for this. On a task's **Arguments** tab, open the lightning-bolt menu next to an argument and choose **Create Input**. It creates a pipeline input for that argument and connects it in one step. **Connect to…** in the same menu connects an argument to an input that already exists.
:::

:::note
Using input nodes as pipeline-wide constants or variables is a great trick and has some benefits:
   - Change the value once to update all connected components
   - Makes pipelines more readable and maintainable
   - Reduces configuration errors
:::
